# Звіт про міграцію AI-агента на Assistants API

**Дата:** 18.11.2025

## 1. Мета

Основною метою було оновлення архітектури AI-асистента VALORANT HUB шляхом переходу з базового **OpenAI Chat Completions API** на більш просунутий **OpenAI Assistants API**. 

## 2. Обґрунтування

Попередня реалізація вимагала ручної обробки історії повідомлень та ланцюжків викликів інструментів на стороні бекенду. Перехід на Assistants API дозволив:
- **Спростити код**: Перекласти логіку керування станом розмови та інструментами на сторону OpenAI.
- **Підвищити надійність**: Використовувати вбудовані механізми OpenAI для керування довготривалими розмовами (`Threads`).
- **Розширити функціонал**: Забезпечити можливість у майбутньому легко додавати нові функції, такі як пошук по файлах (Retrieval) та виконання коду (Code Interpreter).

## 3. Виконані зміни

### 3.1. Створення Асистента на платформі OpenAI

- Було створено постійний об'єкт `Assistant` на платформі OpenAI.
- **Конфігурація асистента**:
  - **Ім'я**: `VALORANT HUB Assistant`
  - **Модель**: `gpt-4o-mini`
  - **Інструкції**: Надано системний промпт, що визначає роль та поведінку асистента.
  - **Інструменти (Functions)**: Усі функції з файлу `api/tools.js` були зареєстровані в налаштуваннях асистента.

### 3.2. Модифікація Backend (`api/chat.js`)

- Файл `api/chat.js` було повністю переписано для роботи з Assistants API.
- **Нова логіка**:
  1. Отримує `message` та опціональний `threadId` від клієнта.
  2. Створює нову розмову (`Thread`), якщо `threadId` не надано.
  3. Додає повідомлення користувача до `Thread`.
  4. Запускає асистента (`Run`).
  5. Асинхронно очікує на завершення `Run`, обробляючи проміжні стани, зокрема `requires_action` для виклику інструментів.
  6. Надсилає результати роботи інструментів назад до OpenAI.
  7. Після успішного завершення (`completed`) отримує фінальну відповідь асистента з історії повідомлень.
  8. Повертає клієнту відповідь та `threadId` для продовження розмови.

### 3.3. Оновлення конфігурації

- Додано нову обов'язкову змінну середовища: `OPENAI_ASSISTANT_ID`.

### 3.4. Оновлення документації

- Файл `AI_DOCUMENTATION.md` було оновлено до версії 2, щоб відобразити нову архітектуру, схему роботи та вимоги до налаштувань.

## 4. Необхідні дії

- **Frontend**: Необхідно оновити клієнтську частину для зберігання `threadId` та передачі його у наступних запитах для підтримки контексту розмови.
- **Vercel**: Потрібно додати змінну середовища `OPENAI_ASSISTANT_ID` у налаштуваннях проекту.

**Результат:** AI-агент успішно мігрував на більш сучасну та потужну платформу, що спрощує його подальшу розробку та підтримку.
